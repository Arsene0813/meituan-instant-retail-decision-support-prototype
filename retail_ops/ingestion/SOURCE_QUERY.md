# 保存上传数据，按日期查询

每天收到的文件按其实际覆盖日期、门店和数据集保存。查询时可以选择自然月，也可以直接填写起止日期。两种选择方式会转换成相同的日期参数，读取同一份已发布数据。查询默认只返回结果，不创建批次、发布版本或查询报告。

## 字段和日期

业务字段改名数为 0，字典中文定义保持原样。

| 现有字段 | 字典定义或已登记用途 | 使用位置 | 是否改名 |
|---|---|---|---|
| `store_id` | 规范门店标识 | 来源归属与查询筛选 | 否 |
| `period_start`、`period_end` | 报表首日、末日，包含末日 | 来源覆盖及查询边界；两者由各自输入明确提供 | 否 |
| `period_month` | 现有自然月数据的月份标签 | 来源完整覆盖自然月时必填，其他来源窗口保持空值 | 否 |
| `transaction_amount` | 所选时间周期内，该账号所选择条件下门店的当天支付且当天未取消的订单用户实际支付金额 | 原值留存及明确登记的日汇总 | 否 |
| `transaction_orders` | 所选时间周期内，该账号所选择条件下门店的当天支付且当天未取消的订单量 | 原值留存及明确登记的日汇总 | 否 |
| `batch_id`、`file_sha256`、`source_line_end` | 批次、原字节摘要和来源记录结束行号 | 查询行追溯 | 否 |
| `publication_id` | 已发布数据版本 | 一次查询固定读取的版本 | 否 |
| `mapping_version` | 已登记的来源解析规则版本 | 区分原月度规范 CSV 和实际日期规范 CSV | 否 |
| `aggregation_scope`、`aggregation_scope_sha256` | 新登记的来源汇总口径声明及其摘要 | 固定已核对的筛选条件、时区和审核人 | 新增来源元数据，无业务字段改名 |

日数据的首尾日期相同。如果每天上传的是“本月截至当天”的累计报表，就保存其真实起止日期，不能把上传日期当成该记录唯一的业务日期。系统不拆分月报、按天均摊或通过累计差额补造原文没有的日数据。

`canonical_csv_v1` 保留原完整自然月规则；`canonical_csv_v2` 接收明确的实际覆盖窗口。v2 仍逐项校验门店、分类、日期、主键、字段类型和原值。完整自然月来源必须提供正确的 `period_month`；日或其他范围来源不填写该标签，也不从上传上下文补值。

v2 的非整月来源只对已明确登记的 `demo2_store_period_metrics`、`store_period_panel_metrics`、两个 Demo 2 SKU 榜和搜索词数据集启用。`store_a_monthly_metrics` 与 `store_a_top_skus` 保持其月度来源规则。格式升级不创建新业务分类，也不改变原数据集的字段含义；上传仍需明确登记其合法去向。

新上传使用 `../contracts/intake_registry.v2.empty.json` 和对应 v2 schema。v2 增加 `canonical_csv_v2` 解析规则及可选的来源汇总口径声明；门店身份、来源页、窗口及文件摘要仍由独立核对的登记提供。

每份 v2 上传登记可以提供 `aggregation_scope`，其字段为 `scope_version`（当前为 `"1"`）、`timezone`（真实业务时区的 IANA 名称）、`selection_conditions`（完整的非日期筛选条件）和 `reviewed_by`（核对人）。日期仍使用来源的实际首尾日。没有筛选也应明确核对；条件未知时省略整个 `aggregation_scope`，不能用空对象或 `null` 冒充核对结果。

该声明只从受信的操作员登记读取，并通过原文件摘要绑定该次上传；CSV 或模型提议不能提供它。发布保留全文和 `aggregation_scope_sha256`，查询检查一致性。它是人工核对的声明，摘要用于固定内容，不等于系统已经认证美团后台或自动验证真实筛选条件。来源条件或时区变化时，不进入原范围的修订链和日汇总。

## 接入与发布

接收仍使用 `batch_cli receive`。每批是一家门店、一个来源窗口和一个数据集；来源文件与登记一致后，重新运行 preview 并归档。相同业务范围的修订必须明确指向前序批次；格式版本变化本身不能绕过修订检查。新版空值不从旧版补回，显式零保留。

接入后的明确批次选择可以发布为来源记录快照：

```bash
python3 -m retail_ops.ingestion.publication_cli publish \
  --database "$HOME/agent/meituan-intake/batches.sqlite3" \
  --directory "$HOME/agent/meituan-publications" \
  --selection "$HOME/agent/meituan-intake/selected_batches.json" \
  --source-records
```

选择文件仍只包含明确的 `batch_ids` 列表。发布会独立重放来源、登记和 preview，原子生成包含原文及规范记录的不可变版本。该动作发生在选择接入数据时，与查询日期无关。多个查询可以反复读取同一个版本。

来源记录快照明确标记 `source_records_v1`，保留实际数据集、来源窗口和逐行 lineage，不投影到其他数据集，也不生成月度 SQL 或 fact。原有月度发布入口继续使用原 SQL/fact/RAC；非完整自然月记录会在生成月度分析前停止。

发布选择不自动追到“最后上传”的记录。相同逻辑窗口的重叠来源要求明确选择一份；不同覆盖范围的来源可以留存，但查询汇总时继续检查重叠，不能混加累计快照。

## 查询

下面的两个命令在相同数据版本下返回相同结果。替换发布 ID 为实际输出值；门店参数使用已登记的规范 ID。

```bash
python3 -m retail_ops.ingestion.source_query \
  --directory "$HOME/agent/meituan-publications" \
  --publication-id 实际发布ID \
  --dataset-id store_period_panel_metrics \
  --store-id B --store-id C \
  --month 2026-03
```

```bash
python3 -m retail_ops.ingestion.source_query \
  --directory "$HOME/agent/meituan-publications" \
  --publication-id 实际发布ID \
  --dataset-id store_period_panel_metrics \
  --store-id B --store-id C \
  --period-start 2026-03-01 --period-end 2026-03-31
```

手选其他首尾日也走同一个函数。入口使用参数化 SQL 在内存中筛选明确的数据集、门店和日期；结果输出到终端。只有执行期间存在临时读取副本，退出后删除。查询不读取批次数据库，不写发布目录，不创建查询报告，也不调用新的发布操作。

来源窗口完全落在查询范围内的记录可逐条展示。较粗的报表如果只与查询部分重叠，会单独说明该窗口存在；它的数字不能作为查询区间的数字。查询结果按门店显示实际记录、来源、日期缺口、指标缺值和重叠情况；一店的记录不补另一店的缺口。

## 指标处理规则

规则登记在 `../contracts/range_query.v1.json`，查询派生结果与上传原值分开返回。原业务字段名继续作为指标键。

- 一条完整店铺来源记录的窗口恰好等于查询窗口，且没有重叠冲突时，可以原样返回该窗口的指标。
- `transaction_amount` 与 `transaction_orders` 允许对完整、互不重叠的每日记录求和。每一天都要有对应值，来源账号、门店绑定及来源页等范围一致，并且每份上传都有相同的已核对 `aggregation_scope`。来源口径未核对、缺日、缺值或存在歧义时，区间总值为空，并给出具体原因。不会把部分和当成整个区间的总值。
- 人数、比例、均价、排名和其他指标保留逐来源窗口的原值。本轮不把不同日期的用户人数相加，也不重算后台没有提供的比例。
- SKU 和搜索词保留各窗口原排名与原记录，不按同名跨日合并，不从每日榜单生成区间榜单。
- 跨店结果逐店呈现，不自动形成全店总人数、经营优劣排名或可复制结论。

后台来源窗口不足以回答查询时，结果会指出所需范围缺少记录。没有数据与显式零继续分别处理。

## 兼容与后续

旧批次库不迁移、不回填新字段。旧原文、控制字段和来源结果继续可读取。代码升级后仍遵守第六步的处理版本核验：旧发布需使用匹配的代码和环境；按新规则发布时须重新核对接收，不改写旧摘要。

规范 CSV 的实际日期接入和只读区间查询已接通。[区间 RAC 与 API](RANGE_API.md) 在同一读取副本内核对来源、覆盖、数值与比较条件，重算假设和判断。已有月度 RAC 继续保留。后续接通已登记中文原文、上传操作和查询界面；自动获取频率在真实后台来源可用后配置。现有月度历史文件、中文原文预览及 Docker API 保持当前入口。
