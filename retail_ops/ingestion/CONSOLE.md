# 本地数据工作台

`api.retail_console_api` 将已有接入、批次发布、日期查询和 RAC 放在同一页面。入口为 `http://127.0.0.1:8001/`。本机操作人先维护独立来源登记，页面从中选择上传标识，再接收原文件。它不编辑门店身份、字段映射或来源收据。

## 配置与启动

在项目根目录运行，沿用处理数据和创建发布时的 `.venv`：

```bash
export MEITUAN_INTAKE_DATABASE="$HOME/agent/meituan-intake/batches.sqlite3"
export MEITUAN_INTAKE_REGISTRY="$HOME/agent/meituan-intake/reviewed_uploads.json"
export MEITUAN_PUBLICATION_DIRECTORY="$HOME/agent/meituan-publications"
.venv/bin/python -m uvicorn api.retail_console_api:app --host 127.0.0.1 --port 8001 --no-access-log
```

登记、数据库和发布目录必须位于仓库之外，不能使用符号链接。批次库或发布目录不存在时，列表显示为空，读取操作不创建文件。登记文件缺失或核对失败时，页面显示具体原因；已有批次与发布的读取功能继续可用。空登记可以采用 `intake_registry.v3.empty.json`，填写规则见 [TEXT_INTAKE.md](TEXT_INTAKE.md) 和 [BATCH_INTAKE.md](BATCH_INTAKE.md)。不要从 B–F 样例推断真实门店身份。

默认只接受 `127.0.0.1:8001`。需要另一个本机端口时，同时设置 `MEITUAN_CONSOLE_AUTHORITY=127.0.0.1:端口` 和 uvicorn 的 `--port`。服务占用当前终端，`Ctrl+C` 停止；浏览器刷新不能重新启动进程。

原 `api.retail_range_api` 仍提供此前只读 API，两者不能同时占用 8001。本工作台使用 `/console/` 接口和独立展示格式，不改变原 `/retail/query`、`/retail/review` 的响应合同。原 Docker 服务仍使用其既有入口。

## 使用顺序

1. **上传数据**：刷新独立登记，选择 CSV 的上传 ID 或中文原文的文档 ID。核对页面显示的门店、实际日期、分类、来源页、提取时间和文件摘要，再选择原文件，点击“核对并留存”。当前文件上限为 8 MiB，使用原始字节，不在浏览器重写 CSV 或中文文本。
2. **修订**：勾选“本次修订已有批次”，为需要修订的每个子数据集填写完整前序批次 ID。页面不自动匹配前序，也不按上传时间覆盖。新版缺值仍为空。
3. **查看接收结果**：通过的批次显示规范记录及来源；待核对结果显示批次原因、来源行错误和解析候选。中文整份待核对时仍可通过其 `quarantine_batch_id` 查看留存结果。
4. **批次与发布**：勾选已通过批次，可以跨页选择；“查看全部已选批次”列出包含其他页的全部选择。“清空选择”明确撤销选择。点击“发布所选批次”后，现有发布程序重新核对来源并生成 `source_records_v1` 版本。同店同窗口的竞争版本仍由现有规则拒绝，不由页面任选一个。
5. **日期查询**：明确选择发布版本、数据分类和门店，选择自然月或首尾日期。两种日期选择进入同一后端查询。页面显示区间值、各指标缺值记录数、实际来源窗口和部分重叠窗口，不将部分覆盖的月报值当作所选区间值。
6. **RAC**：店铺期间数据可以运行 RAC。一个门店可另选较早基准区间；多个门店使用同一所选区间。页面显示本次报告、检查与差值、竞争假设及仍需核对的条件。判断状态不表示经营建议已经可以执行。

上传、接收结果和明确的发布版本留存。查询和 RAC 只返回本次结果，页面不使用查询历史、localStorage 或自动保存报告。切换版本、日期或字段后清除旧结果，迟到请求不能覆盖新选择。

## 字段与展示

业务字段继续沿用字典定义，不改名。字段选择来自现有 `SCHEMAS`，中文标签优先取 `DATA_DICTIONARY.md`，再使用已登记原文标签；没有标签时显示原字段名。`gross_revenue` 虽已有字典定义，当前数据集尚未接入，因此不出现在可用字段中，也不会用“营业额”称呼 `transaction_amount`。

| 现有字段 | 字典定义或既有用途 | 工作台使用位置 | 是否改名 |
|---|---|---|---|
| `store_id`、`period_start`、`period_end` | 规范门店和实际来源首尾日 | 登记核对、批次选择和日期查询 | 否 |
| `transaction_amount`、`transaction_orders` | 字典中的成交金额、成交订单量 | 区间原值及 RAC 检查 | 否 |
| `sku_transaction_amount`、`sales_volume` | 商品成交金额、销量，分别保留榜单依据 | 原始窗口记录 | 否 |
| `batch_id`、`publication_id`、`file_sha256`、`source_locator` | 已登记批次、版本、原文件摘要及原文定位 | 选择明确证据并展开原文片段 | 否 |
| `registry_sha256` | 独立登记的原字节摘要 | 页面读登记后，上传前核对是否已变化 | 否 |

工作台专用响应为 `{"number_encoding":"decimal_text","data":...}`。`data` 内所有数值叶子使用精确十进制文本；布尔值和 `null` 保持类型。转换在服务器完成，防止浏览器把超过 `2^53-1` 的整数舍入。业务字段名不变，数据库和原查询 API 的类型不变。页面不计算合计、比率或差值。

`kind`、`selection_id`、`source_base64`、`supersedes` 是本地接收请求参数。它们分别选择已有 CSV/document 登记、传递原始文件字节和明确前序关系，不是业务指标或新的来源证据。发布请求只包含明确 `batch_ids`；查询请求复用现有日期、门店、字段选择模型。请求不能提供数据库路径、登记内容、模型提议或替代来源。

## 请求与版本核对

页面使用进程内随机 token、本机 Host 与同源 Origin 检查，禁止跨站调用本地操作接口。token 不进入 URL，页面及数据响应不缓存。请求体在 JSON 解析前按实际接收字节限长，原文展示使用文本节点。这是单机操作入口，不提供多用户登录或美团后台账号认证。

上传时读取并核对独立登记与身份文件，确认页面所见 `registry_sha256` 后，用这些确切原字节创建本次私有快照，再交给既有接收程序。登记文件在此后变化不会让本次接收换用另一份依据。页面仍无法证明后台本身的真实性；真实来源绑定继续由独立核对负责。

本步不修改接入处理程序、字典、发布 recipe 或 RAC 规则，第九步已创建的批次与发布版本继续使用原有校验。列表会核对批次原字节、内部控制字段和发布文件摘要，损坏或与当前规则不符的版本不作为可用查询版本。读取没有默认“最新”回退。

测试使用合成原文，覆盖接收、发布、修订、查询与 RAC，包含空值／零、大整数精度、登记竞态、请求边界和不落盘的读取操作。真实后台授权获取与定时采集仍需在实际来源接口明确后接入。
