# 中文整理格式的预览

`manual_text_v2` 对应本次附件的整理格式：每个区块有 `店铺：B` 这样的门店行和 `时间范围2026.3` 这样的窗口行。店铺指标每行一项，搜索词和两类 SKU 榜使用已登记的单行标题。

来源配置位于 `retail_ops/contracts/manual_text.v2.json`。数据先按原文拆分，再调用已安装的 `preview_csv` 校验；整个过程输出预览 JSON。

`manual_text_v1` 的配置保留原样，供核对此前的预览。本次简称映射使用 `manual_text_v2`，输出同时记录所选版本和配置文件摘要。

## 类型与上下文

- 店铺期间指标使用 `store_period_panel_metrics` 的校验规则。
- 搜索词榜使用 `demo2_top_search_terms`，粒度为 `store_search_term_period`。
- 销量榜使用 `demo2_top_skus_by_sales_volume`，排名依据为 `sales_volume`。
- 成交金额榜使用 `demo2_top_skus_by_transaction_amount`，排名依据为 `transaction_amount`。

这些 ID 选择明确的校验规则。入口不向对应样例 CSV 写入数据，也不把当前配置当作真实上传库的默认存储目标。

当前别名表只登记了 B–F。单店上传可以额外提供 `--expected-store-id`；多店上传可以重复提供该参数。它由上传端传入，不能由模型改写。真实美团账号、门店 ID 和店名关系仍需单独接入。

窗口支持 `2026.3`、`2026-03`、`2026.2.1-2.28` 这样的完整自然月形式。一个新窗口需要新的门店区块。店铺行或窗口行缺失时，不从前文或上传时间猜测归属。

## 原文格式与待核对项

店铺指标用明确标签匹配，不使用相似词回退。遇到未知字段或新报表标题时，从该行起暂停解析当前区块，直到新的店铺区块出现。这样后面的数字不会继承上一报表的归属。

搜索曝光、搜索入店、商家列表曝光、商家列表入店、活动专区曝光、活动专区入店、订单页入店、其他入店这八个简称使用上表中的对应字段。来源未提供数值时仍为 `null`，明确的 `0` 保留。简称和完整名称若在同一店铺期间重复出现，按重复指标处理，不任选其中一个值。

比例值在此文本格式中需要 `%`，只去掉这个显示符号，保留现有 `*_pct` 的数值单位。未提供的指标、英文辅助名称和品类备注均保持 `null`。不根据其他字段计算或补齐源数据。

榜单按括号外的逗号分隔三项。销量必须带“销量”标签；搜索词计数必须带曝光次数、点击次数或成单次数标签。已给出条目但少了某项数值时保留为空，整个榜单不足三项时待核对。

本附件的成交金额榜使用“商品名 + 末尾数字 + 元”格式，来源配置将末尾连续数字视为金额。新文本中商品名若以数字结尾，应写成 `示例商品2026（成交金额100元）`，明确名称与金额的边界。没有明确区分名称与数值的其他写法需要核对。

同名商品在不同排名上分别保存，不据此合并 SKU。两个排名依据分别保存，没有展示的另一个指标不补值。

## 输出与运行

```bash
.venv/bin/python3 -m retail_ops.ingestion.text_preview --input meituan_notes.txt --profile manual_text_v2 --summary
```

去掉 `--summary` 可查看候选记录及来源行。`file_sha256` 和来源行号对应实际输入文本；各组 `schema_sha256` 对应下游 CSV 校验规则。来源配置、字典与解析代码也分别记录摘要。

输出状态为 `validated` 时，本模块的检查全部通过，退出码为 0。有未知内容、单位待确认、归属冲突、重复数据或提议不一致时，状态为 `quarantined`，退出码为 2，顶层 `validated_records` 为空。候选记录用于核对，不用于发布分析数据。

可选 `--proposals` 读取与候选记录同顺序的 JSON 数组，每项格式与 CSV 入口一致。顺序为原文区块顺序，每块先店铺期间记录，再按原文顺序排列榜单记录。模型提议逐项对照独立解析的原文；提议不能覆盖门店、窗口、分类或数值。
